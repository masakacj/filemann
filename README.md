# FileMann

FileMann EasySign 单 App 版：本地媒体库、逐帧播放器和 WebDAV/NAS 归档合并为一个主界面。

## NAS 传输协议与公网安全

FileMann 现在仅使用 **WebDAV** 进行 NAS 浏览和归档：局域网 WebDAV 优先，无法连接时尝试外网 WebDAV **HTTPS**。旧版存储的 SMB 设置只供兼容迁移，不再出现在设置 UI，也不会启动 SMB 上传任务。

- 公网禁止暴露 SMB TCP 445、NetBIOS 137–139，也不建议公网直连 NAS 管理界面；优先采用 VPN / Zero Trust 私有访问。
- 如必须提供公网 WebDAV，仅通过可信 TLS 证书的 HTTPS 反向代理连接，并配置独立归档账号、最小读写权限、限制登录尝试次数与日志告警；对 FileMann 需支持 PROPFIND、PUT、MOVE、DELETE 等方法。
- 本地 HTTP 仅在私有 LAN 地址上允许；公网连接始终强制 HTTPS。对于自有 NAS 的不受信任证书，可在“远程 WebDAV → 高级”明确同意启用**仅对此 NAS URL 生效**的证书兼容模式；修改地址时自动撤销，默认关闭。兼容模式无法防范中间人攻击，请仅在你确认的 NAS 上使用。也可以保留严格校验并通过 SHA-256 指纹固定信任单张服务器证书。
- 选择归档文件夹时须从 **WebDAV 根目录**浏览，点击“验证写入并选择”：仅在该现有目录成功完成独立临时文件的 PUT、MOVE、DELETE 后才保存。此前从 SMB 共享继承的 `storage/Documentsf/Apps` 不能视作有效 WebDAV 路径；配置中心已撤回未经验证的 `192.168.233.233:8900` 和该 SMB 目录默认值。
- 同步前用临时测试文件检查真实 PUT 写入；支持 MOVE 的 NAS 使用临时上传再重命名，不支持 MOVE（403/405/501）的 NAS 自动切换到 **PUT 直传模式**，并使用 `If-None-Match: *` 防止覆盖既有文件。DELETE 权限不再成为上传的强制条件。
- 重复文件扫描改为逐级 `PROPFIND Depth: 1`，不再发送常被 NAS/Apache 禁止的 `Depth: infinity`；同批次共用扫描清单，避免每个文件重复遍历。不可读取的子目录会跳过，归档根目录仍必须可访问。
- PUT 直传发生网络中断时可能留下未完成的同名远端文件；重试不会覆盖该文件，需先检查或清理。对大文件需要真正断点续传时，仍取决于 NAS 是否支持相应协议。
- 403 错误会标记 PROPFIND、MKCOL、PUT 或 MOVE 等具体阶段。**目录能列出不代表可以上传。**
- iOS 后台 URLSession 可接管文件上传，但 NAS 若不支持 HTTP resumable upload，网络中断后的重试可能需要重传完整文件；当前不能保证字节级续传。URLSession 也可能创建上传临时副本，完成后由系统回收。
- NAS 私密账号及外网地址只保存在个人配置中心，不能写进 GitHub。

## iOS 锁屏 / 后台传输恢复（2026-11-03）

- **灵动岛/Live Activity 不能保活 App**。ActivityKit 仅能呈现进度；真正传输通过系统管理的 `URLSessionConfiguration.background`，使用文件上传和固定 session identifier。锁屏、切换 App、由系统回收进程时，系统后台守护进程可继续执行已提交任务；用户从多任务界面强制上划关闭 App 时，iOS 会取消该 App 的后台传输，无法通过灵动岛绕过。
- **修复系统唤醒**：处理 `application(_:handleEventsForBackgroundURLSession:completionHandler:)` 时立即以相同 identifier 重建后台 URLSession，避免 UI 不出现时未能关联原系统任务。
- **等待 NAS 最终确认**：`didCompleteWithError` 的 PUT 成功并不等于正式归档。必须完成原端点的临时文件尺寸核验、MOVE（若支持）及父目录 PROPFIND 确认后才写入成功结果；`urlSessionDidFinishEvents` 会等待这些异步核验结束后再向 UIKit 通知本轮事件处理完毕。
- **断进程恢复日志**：校验成功后先把任务 ID、原上传端点、实际文件路径和大小写入原子化 Application Support 收据，再通知 UI。如果系统唤醒时 UI 尚未装载，下一次启动会从收据恢复完成状态；严格匹配任务 ID/端点/路径/大小，不能跨端点或误认其他文件为上传成功。失败信息同样写入独立收据。
- **续传前恢复远端原件**：前台重新打开 FileMann 时，对原批次中断任务仅访问其原始 WebDAV 端点，若最终文件已严格通过目录确认就恢复已完成状态；若任务专属的完整 `.filemann-<UUID>.partial` 文件存在，尝试完成 MOVE 并验证。未完整落盘的临时文件不能被标为成功。
- **提前提交更多小媒体**：最多预提交 **16 个**小媒体，暂存预算 **160 MiB**；实际 HTTP 并发按已连通的 WebDAV 端点区分：局域网最多 **4 路**、公网最多 **2 路**。局域网 16–64 MiB 媒体最多 2 个并发，超过 64 MiB 的大视频始终单传。iOS 系统决定实际后台执行时机。
- **尊重暂停和网络策略**：用户点“暂停/清空”即撤销自动续传意图；用户主动开始的队列在下次打开 App 时可以恢复，失败/重复冲突仍要求显式处理。使用 Wi-Fi only 时网络变化会影响调度，且 iOS 可因省电/网络策略延迟后台启动。
- iOS 原生 **HTTP 可恢复上传**需要 NAS/WebDAV 服务端支持相应协议，不能承诺对任意 QNAP WebDAV 大文件做到字节级断点续传；本改版保证的是系统后台任务重关联、可靠落盘确认与恢复已完成文件，避免不必要的全量重传。
- 灵动岛可以日后作为**状态展示**单独开发，但由于 iOS 后台限制及 Live Activity 更新途径，不把灵动岛称为保活方案。

## WebDAV 批量上传性能优化（2026-11-03）

- 原先每完成一个 HEIC 文件就会重新连接 NAS、重新执行 PUT/MOVE 权限测试并重复扫描整个目录内的同大小文件；新版在同一批次内复用**原 WebDAV 端点、已确认的上传模式、重复文件扫描结果与目录可写状态**。已归档项不再被纳入“待上传同大小文件”计数；恢复中的 URLSession 活跃任务也不会再次参与重复扫描。手动重新开始、修改配置、暂停或清空队列会重新检查，避免跨会话使用过期判断。
- iOS 后台 URLSession 已按端点拆成独立会话：探测确认可用的私有局域网地址采用 **4 路**小文件 HTTP 并发；外网 HTTPS 仍为 **2 路**。局域网 **16–64 MiB** 的文件最多 2 路，超过 **64 MiB** 的视频保持单传，预暂存总预算仍是 160 MiB。升级后原会话标识继续保留，只用于恢复旧版本遗留的后台任务。
- 原先每个 URLSession 进度回调都会重新保存整个归档任务数据库（高频次磁盘写入）；现在 UI 约 0.25 秒刷新一次，传输断点和速率每秒保存一次，完成/失败时仍立刻持久化。
- **最后整批核验**按「实际上传的 WebDAV 端点 + 父文件夹」合并检查，使用每个父文件夹的一份真实 Depth:1 PROPFIND 列表逐一验证原文件名及字节数。不退化到 HEAD-only 校验、不跨本地/WAN 端点判断、不删除 NAS 原件。单文件完成时仍单独执行严格落盘核验。
- HEAD 明确返回 404/410 时直接认定目标路径不存在，不再额外请求一次重复的 PROPFIND。HEAD 不受支持、无尺寸或响应异常时仍执行目录查询回退。
- 「传输」标签页显示**当前总上传速度（按多个活动上传合计）**和实际使用的本地/远程 WebDAV 端点。若配置走远程而 iPhone 与 NAS 在同一 Wi-Fi，会提示优先检查本地地址，避免不必要的公网绕路。
- 运行时性能改善取决于网络/NAS/WebDAV 网关；该改版只消除固定开销与提升小文件流水线，**不保证提高单个大型文件的物理网络带宽**。

## 重复文件：全部保留 NAS（2026-11-03）

- 「处理重复」顶部增加醒目的 **全部保留 NAS（N 项）** 按钮。即使只有一项待处理重复文件也显示；确认后将所有**尚未执行**的重复处理项统一选择「只保留 NAS」，包括之前暂时选择「只保留手机」或「两边都保留」但尚未执行的项。
- 已完成、已跳过任务不会被反向修改；按钮本身只保存选择，不在重复文件页面执行任何删除操作，也不删除 NAS 副本。
- 点击「开始/继续归档」后，需要对现有 NAS 文件重新严格核对，并通过整批远端清单校验，才会清理明确选择「只保留 NAS」的手机副本。此显式选择**不依赖「归档后自动删除」全局开关**；选择「两边都保留」仍会阻止自动删除该手机副本。
- 校验失败、存在未完成任务时不会执行整批删除。

## 局域网并行传输及恢复扫描（2026-11-03）

- 只有**实际探测成功的私有局域网 WebDAV 地址**会启用 4 路并发；连接失败并回退到外网 HTTPS 后，自动使用独立的 2 路后台会话。旧版已提交的 URLSession 任务仍可凭原 session identifier 恢复，不会因升级丢失。
- 文件字节数恰好相同不代表重复：局域网同大小文件允许先通过本地流式 SHA-256 确认**内容不同**后并行；若内容相同或读取失败，继续串行等待 NAS 的严格重复校验。SHA-256 仅用于局域网传输调度，不代替远端完整字节比较或归档落盘核验。
- **恢复是否扫描**：同一进程内的批次复用已获取的目录清单；恢复后台收据、已提交任务，以及确认前次中断的原目标路径时不扫描全 NAS。App 被系统终止后若仍有**未上传的新任务**，恢复时仍可能对这些待处理文件重建一次逐层 Depth:1 NAS 清单，以发现期间新增的外部重复文件。不能把“跳过扫描”当作去重正确性的证明。
- 暂存预算和单大文件限制保持不变；锁屏可由 iOS 继续处理已提交任务，但用户强制关闭 App、NAS 不支持字节范围续传或 iOS 调度限制仍可能导致任务中断或重新传输。

## 本地原片同步文件夹的媒体库布局（2026-11-03）

- 「本地」媒体库现在按**拍摄时间优先（读取 HEIC/JPEG 的 EXIF 原始拍摄时间）**分日期展示。EXIF 缺失或视频无日期时使用文件修改时间；**同一时间**的媒体按原文件名自然排序（例如 `IMG_2.HEIC` 排在 `IMG_10.HEIC` 前），不再每次刷新随机跳位。
- 在相册网格上方可以看到照片/视频数量，切换**缩略图网格 / 详细文件列表**，排序支持拍摄时间正序/倒序、原文件名正序/倒序、文件修改时间倒序，选择会记忆。
- 每张缩略图都占用固定正方形位置，下面显示两行**完整原文件名预览**，角落显示真实扩展名（HEIC/MOV/JPEG）；列表模式另外显示大小和日期。媒体文件仍保持原目录、原名称及原格式。
- 「NAS 归档」面板默认收起，即使队列中有 200+ 个任务，展开也只展示最多四项摘要，完整任务仍在底部**「传输」**标签页，避免任务列表把照片网格挤出屏幕。
- 隐藏相册的「导出未修改的原片」可能同时生成 HEIC、MOV、AAE 辅助文件。AAE 等非媒体附属文件不参与缩略图展示，不会被清理或删除；HEIC/MOV 仍是独立原件，可按文件名排序检查配对。

## HEIC 原始格式导入（2026-11-03）

- **iOS「照片」分享**：选择照片后点「分享 → 选项 → 格式 → 当前（Current）」以避免 iOS 自动把 HEIC 转成 JPEG。FileMann 分享扩展会在系统实际提供的格式中**优先请求 HEIC / HEIF**，而不是按枚举顺序误选 JPEG。
- **FileMann「传输」标签页 → 从相册导入原格式（优先 HEIC）**：使用 iOS `PHPickerConfiguration.preferredAssetRepresentationMode = .current` 选择照片/视频；系统可提供 HEIC 原格式时，FileMann 只复制文件字节，不调用 UIImage 转码。可选多项，逐项暂存到持久化队列。该选项是“避免转码”的优先模式，不能强迫系统生成它没有提供的原始表示。
- **原名与格式双重校验**：保留提供方真实文件名；针对 HEIC 数据检测文件头（HEIF `ftyp`），发现声称 HEIC 却收到 JPEG 时拒绝把 JPEG 假装成 HEIC，提示更换分享格式。若系统仅提供 JPEG、没有原 HEIC，FileMann 无法通过修改扩展名恢复 HEIC 原件。
- **HEIC 文件名修正**：如果提供方同时给出临时 JPEG 名称与真正的 HEIC 文件名，优先使用与实际 HEIC 字节相符的文件名；原名未提供时仍在 FileMann 队列标记“待确认文件名”，可以根据预览和选择序号自定义或授权使用占位名。
- **已转成 JPEG 的历史上传**不会被原地改扩展名。需要从相册重新导入相应原始 HEIC，避免在 NAS 上覆盖或伪造文件。

## 2026-11-03：未命名媒体和全量任务清理

- iOS Photos 在批量分享时可能只返回 `shared-media.mp4` 这样的通用文件名。FileMann **不再将媒体直接拒绝**：文件字节照常暂存到 App Group，并附带原选择位置（例如第 29 项）和“待确认文件名”的本地元数据。
- 打开 FileMann 的 NAS 归档任务列表，可点击“只看待命名”，利用**相册选择序号、缩略图和文件大小**定位。每项可选择“自定义文件名”或“使用占位名”；不选择前，该项不自动上传，其他正常任务可继续。
- 占位名称仅用于本地暂存，只有用户**明确选择**“使用占位名”后才允许上传。原名已知的照片和视频继续完整保留原文件名；同名依旧只追加 `(2)`、`(3)` 等数字后缀。
- “清空全部任务”同时提供在本地归档列表和内嵌归档面板，需二次确认，取消 FileMann 后台上传并清除任务记录/重复决策/分享扩展暂存及附属元数据。**不删除照片原件、不删除 NAS 上已有文件、不移除已保存的源目录位置。**
- 旧版本已拒绝并未暂存的素材无法凭空恢复；例如此前 213 项中第 29 项失败，需再次从相册分享那一项。其余已暂存项目升级后仍可导入。
- GitHub iOS CI 的测试验证：第 29 项通用文件名可以暂存并保留序号、原文件名正常保留、两个未知名称不会互相覆盖、清理分享暂存不影响原始来源文件。

## 相册批量分享（200+ 项）

- Share Extension 的 `NSExtensionActivationRule` 现声明最多 **1024 个附件**，图片、视频与文件的单类最大值也设置为 1024。此前三个数值均为 25，超过上限时 iOS 会在分享列表中隐藏 FileMann。
- 分享扩展会逐项处理，显示当前项 / 总数、成功暂存和失败计数。失败/不支持的单项不会回滚已经保存在 App Group 中的其他文件；出现部分失败时，会要求用户确认“完成（保留已导入项目）”，并显示实际计数。之后需要在相册重新选择失败/未处理的项目。
- 单项无法获取可信原始文件名时仍遵循“保持原名”的规则，**拒绝生成假的随机名**。正确的项仍可进入队列。
- 由于 iOS 分享扩展有执行时间、空间与宿主分享能力限制，**配置允许显示 200+ 项不等于保证一次可完成数百个超大视频**；建议必要时分批。重新打开 FileMann 主 App 后，成功暂存的项目会恢复到持久化队列。
- 不会因为分享成功就删除相册原件。若 iOS 不提供 in-place 文件访问，暂存可能需要临时磁盘空间；真实 NAS 校验之后才自动清理分享临时副本。

## 归档成功判定与文件名（2026-11-02）

- “完成”不再仅依据 HTTP HEAD 的大小：必须在**本次实际上传的 WebDAV 端点**对目标父目录执行 PROPFIND Depth:1，找到**准确的文件名和文件大小**才显示已落盘。不允许在本地上传失败后拿另一个 WAN 入口的同名文件冒充成功。
- 对每个传输任务记录实际 WebDAV URL 与归档文件路径，可在任务中复制 URL；单独提供“核验已完成文件”只读核查旧记录。旧版成功记录没有可信入口凭证时只作为候选位置，不再用旧校验结果自动删除手机文件。
- 已有重复文件将明确标成“复用 NAS 已有副本，未新增文件”，与新上传区分。
- 从 iOS 相册分享时，优先使用照片/视频提供的真实文件名；`shared-media.mp4` 等通用占位名不会直接用于新任务。若系统未向扩展暴露原名，使用唯一的日期视频／图片名，并允许在**尚未上传**时手动修改文件名。已上传的旧任务无法凭旧临时副本推算原照片名。
- 诊断及验证只读，不会为修复路径问题自动移动或覆盖 NAS 既有媒体。

FileMann：

```
… → 快捷指令复制后询问删除相册原件
```

这个开关会同步到：

```
我的 iPhone / FileMann / FileMann Shortcut Settings.txt
```

文件内容为：

```
ask_delete_originals=1
```

或：

```
ask_delete_originals=0
```

快捷指令可以读取这个文件，只有值为 1 时才显示“是否删除相册原件？”确认，然后把最初的“快捷指令输入”交给“删除照片”。

这样开关由 FileMann 控制，但真正的相册删除仍由持有原始 Photos 输入的快捷指令完成，避免 FileMann 根据文件名猜测照片身份。

## FileMann 内相册导入

```
FileMann → 右上角照片+
```

这一条通过 PhotoKit asset identifier 精确删除，因此仍可使用：

```
FileMann 导入后清理相册原件
```

## 签名与 Bundle ID

FileMann 固定使用独立 Bundle ID：

```
com.masakacj.filemann
```

不要再改成 `tg.unitgqq2709.tool1`，因为该 Bundle ID 已被其他 App 使用；iOS 会把相同 Bundle ID 视为同一个 App，从而发生覆盖安装。

你当前上传的 mobileprovision 是精确绑定到：

```
tg.unitgqq2709.tool1
```

因此这份描述文件不能用于安装当前这个独立 Bundle ID 的 FileMann。需要另一份匹配 `com.masakacj.filemann` 的描述文件，或者允许自定义 Bundle ID 的 wildcard profile。

IPA 不包含 Share Extension，也不依赖 App Group。

## WebDAV 本地 / 远程双地址

WebDAV 现在支持两个地址：

```
本地地址  http://192.168.x.x:5000/Share
远程地址  https://nas.example.com/Share
```

连接策略固定为：

```
先探测本地地址
→ 本地可达：使用本地
→ 本地不可达：自动使用远程
```

归档、目录浏览和 NAS 媒体浏览都使用同一套策略。

外网 WebDAV 只接受可信 HTTPS，HTTP 公网连接不会进入上传候选列表；证书错误不会被忽略。

## NAS 媒体浏览

主界面右上角的“云盘”按钮可以直接浏览当前 WebDAV 归档目录中的图片和视频。

- 目录使用 WebDAV PROPFIND 懒加载。
- 图片缩略图只在进入屏幕后按需下载，并写入本地缩略图缓存。
- 图片全屏查看支持双指放大。
- 视频使用 AVAssetResourceLoader + HTTP Range 分段读取，不会先完整下载视频再播放。
- 远程视频保留 FileMann 的手势播放器：
  - 左侧点击：上一帧
  - 右侧点击：下一帧
  - 中间点击：播放 / 暂停
  - 左侧长按：1.5× 倒退
  - 右侧长按：1.5× 快进
  - 下方区域长按并左右拖动：逐帧拖动
  - 双指：局部放大
- 视频 Range 请求会优先使用当前可用的本地地址，并保留远程地址作为备用。


## 独立 NAS Tab

主界面现在分成两个底部 Tab：

```
本地
NAS
```

“本地”负责手机媒体、快捷指令导入和归档任务；“NAS”专门负责 WebDAV 远程目录、图片和视频浏览。NAS Tab 仍然使用本地优先、远程失败回退策略。


## 缓存管理

设置页新增缓存管理：

- 显示当前缓存占用。
- 可一键“清理缓存”。
- 最大缓存支持 256 MB / 512 MB / 1 GB / 2 GB / 4 GB，默认 512 MB。
- NAS 原图、NAS 缩略图统一计入总上限，超过上限后按最久未使用顺序自动淘汰。
- 启动时会清理旧版本遗留的 URLSession 网络磁盘缓存。
- 清理缓存不会删除本地媒体库、Shortcut Inbox、归档任务或 NAS 文件。


## 存储占用

设置页会分别显示：

- FileMann 私有本地媒体（Application Support / FileMann / Media / Originals）
- Shortcut Inbox
- NAS 图片/缩略图缓存
- 元数据与临时文件
- 可管理合计

“清理 NAS 缓存”只清可重建缓存；如果 iPhone“存储空间”仍显示数 GB，通常是历史导入到 FileMann 私有媒体库的原图/视频。

可通过“删除 FileMann 本地媒体”单独清理这些文件。存在未完成归档任务时，该操作会被禁用，避免误删仍待上传的源文件。外部映射文件夹和 NAS 文件不会被删除。
