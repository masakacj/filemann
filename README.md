# FileMann

FileMann EasySign 单 App 版：本地媒体库、逐帧播放器和 WebDAV/NAS 归档合并为一个主界面。

## NAS 传输协议与公网安全

FileMann 现在仅使用 **WebDAV** 进行 NAS 浏览和归档：局域网 WebDAV 优先，无法连接时尝试外网 WebDAV **HTTPS**。旧版存储的 SMB 设置只供兼容迁移，不再出现在设置 UI，也不会启动 SMB 上传任务。

- 公网禁止暴露 SMB TCP 445、NetBIOS 137–139，也不建议公网直连 NAS 管理界面；优先采用 VPN / Zero Trust 私有访问。
- 如必须提供公网 WebDAV，仅通过可信 TLS 证书的 HTTPS 反向代理连接，并配置独立归档账号、最小读写权限、限制登录尝试次数与日志告警；对 FileMann 需支持 PROPFIND、PUT、MOVE、DELETE 等方法。
- 本地 HTTP 仅在私有 LAN 地址上允许；公网连接始终强制 HTTPS。对于自有 NAS 的不受信任证书，可在“远程 WebDAV → 高级”明确同意启用**仅对此 NAS URL 生效**的证书兼容模式；修改地址时自动撤销，默认关闭。兼容模式无法防范中间人攻击，请仅在你确认的 NAS 上使用。也可以保留严格校验并通过 SHA-256 指纹固定信任单张服务器证书。
- 选择归档文件夹时须从 **WebDAV 根目录**浏览，点击“验证写入并选择”：仅在该现有目录成功完成独立临时文件的 PUT、MOVE、DELETE 后才保存。此前从 SMB 共享继承的 `storage/Documentsf/Apps` 不能视作有效 WebDAV 路径；配置中心已撤回未经验证的 `192.168.233.233:8900` 和该 SMB 目录默认值。
- 同步前用临时测试文件检查真实 PUT 写入；支持 MOVE 的 NAS 使用临时上传再重命名，不支持 MOVE（403/405/501）的 NAS 自动切换到 **PUT 直传模式**，并使用 `If-None-Match: *` 防止覆盖既有文件。DELETE 权限不再成为上传的强制条件。
- 重复文件扫描改为逐级 `PROPFIND Depth: 1`，不再发送常被 NAS/Apache 禁止的 `Depth: infinity`；同批次共用扫描清单，避免每个文件重复遍历。不可读取的子目录会跳过，归档根目录仍必须可访问。
- PUT 直传发生网络中断时可能留下未完成的同名远端文件；重试不会覆盖该文件，需先检查或清理。对大文件需要真正断点续传时，仍取决于 NAS 是否支持相应协议。
- 403 错误会标记 PROPFIND、MKCOL、PUT 或 MOVE 等具体阶段。**目录能列出不代表可以上传。**
- iOS 后台 URLSession 可接管文件上传，但 NAS 若不支持 HTTP resumable upload，网络中断后的重试可能需要重传完整文件；当前不能保证字节级续传。URLSession 也可能创建上传临时副本，完成后由系统回收。
- NAS 私密账号及外网地址只保存在个人配置中心，不能写进 GitHub。

## 2026-11-03：未命名媒体和全量任务清理

- iOS Photos 在批量分享时可能只返回 `shared-media.mp4` 这样的通用文件名。FileMann **不再将媒体直接拒绝**：文件字节照常暂存到 App Group，并附带原选择位置（例如第 29 项）和“待确认文件名”的本地元数据。
- 打开 FileMann 的 NAS 归档任务列表，可点击“只看待命名”，利用**相册选择序号、缩略图和文件大小**定位。每项可选择“自定义文件名”或“使用占位名”；不选择前，该项不自动上传，其他正常任务可继续。
- 占位名称仅用于本地暂存，只有用户**明确选择**“使用占位名”后才允许上传。原名已知的照片和视频继续完整保留原文件名；同名依旧只追加 `(2)`、`(3)` 等数字后缀。
- “清空全部任务”同时提供在本地归档列表和内嵌归档面板，需二次确认，取消 FileMann 后台上传并清除任务记录/重复决策/分享扩展暂存及附属元数据。**不删除照片原件、不删除 NAS 上已有文件、不移除已保存的源目录位置。**
- 旧版本已拒绝并未暂存的素材无法凭空恢复；例如此前 213 项中第 29 项失败，需再次从相册分享那一项。其余已暂存项目升级后仍可导入。
- GitHub iOS CI 的测试验证：第 29 项通用文件名可以暂存并保留序号、原文件名正常保留、两个未知名称不会互相覆盖、清理分享暂存不影响原始来源文件。

## 相册批量分享（200+ 项）

- Share Extension 的 `NSExtensionActivationRule` 现声明最多 **1024 个附件**，图片、视频与文件的单类最大值也设置为 1024。此前三个数值均为 25，超过上限时 iOS 会在分享列表中隐藏 FileMann。
- 分享扩展会逐项处理，显示当前项 / 总数、成功暂存和失败计数。失败/不支持的单项不会回滚已经保存在 App Group 中的其他文件；出现部分失败时，会要求用户确认“完成（保留已导入项目）”，并显示实际计数。之后需要在相册重新选择失败/未处理的项目。
- 单项无法获取可信原始文件名时仍遵循“保持原名”的规则，**拒绝生成假的随机名**。正确的项仍可进入队列。
- 由于 iOS 分享扩展有执行时间、空间与宿主分享能力限制，**配置允许显示 200+ 项不等于保证一次可完成数百个超大视频**；建议必要时分批。重新打开 FileMann 主 App 后，成功暂存的项目会恢复到持久化队列。
- 不会因为分享成功就删除相册原件。若 iOS 不提供 in-place 文件访问，暂存可能需要临时磁盘空间；真实 NAS 校验之后才自动清理分享临时副本。

## 归档成功判定与文件名（2026-11-02）

- “完成”不再仅依据 HTTP HEAD 的大小：必须在**本次实际上传的 WebDAV 端点**对目标父目录执行 PROPFIND Depth:1，找到**准确的文件名和文件大小**才显示已落盘。不允许在本地上传失败后拿另一个 WAN 入口的同名文件冒充成功。
- 对每个传输任务记录实际 WebDAV URL 与归档文件路径，可在任务中复制 URL；单独提供“核验已完成文件”只读核查旧记录。旧版成功记录没有可信入口凭证时只作为候选位置，不再用旧校验结果自动删除手机文件。
- 已有重复文件将明确标成“复用 NAS 已有副本，未新增文件”，与新上传区分。
- 从 iOS 相册分享时，优先使用照片/视频提供的真实文件名；`shared-media.mp4` 等通用占位名不会直接用于新任务。若系统未向扩展暴露原名，使用唯一的日期视频／图片名，并允许在**尚未上传**时手动修改文件名。已上传的旧任务无法凭旧临时副本推算原照片名。
- 诊断及验证只读，不会为修复路径问题自动移动或覆盖 NAS 既有媒体。

## 主界面

不再使用独立“归档”Tab。

媒体页面顶部会在有归档任务时显示 NAS 归档卡片，包括：

- 总进度、速度
- 暂停 / 继续
- 重复文件处理
- NAS 双边校验结果
- 单任务状态
- WebDAV / NAS 设置

媒体多选后直接点：

```
归档到 NAS
```

即可加入并启动归档。

## 缩略图大小

右上角：

```
… → 缩略图大小
```

支持紧凑 / 小 / 中 / 大，选择会自动记忆。

## 视频播放

- 上一帧 / 下一帧：点按精确逐帧
- 按住上一帧 / 下一帧：连续逐帧
- 长按视频画面：临时 2× 播放，松手恢复
- 双指：局部放大

“视频调整”默认收起，点击后展开。

视频调整只作用于**当前这一次播放会话**：

- 不改写源文件
- 不保存 sidecar
- 退出视频后自动还原
- 不影响其他视频

## 快捷指令分享

中转目录：

```
我的 iPhone
└─ FileMann
   └─ Shortcut Inbox
```

FileMann 会把快捷指令复制进来的图片 / 视频移动到私有媒体库。

### 删除相册原件开关

FileMann：

```
… → 快捷指令复制后询问删除相册原件
```

这个开关会同步到：

```
我的 iPhone / FileMann / FileMann Shortcut Settings.txt
```

文件内容为：

```
ask_delete_originals=1
```

或：

```
ask_delete_originals=0
```

快捷指令可以读取这个文件，只有值为 1 时才显示“是否删除相册原件？”确认，然后把最初的“快捷指令输入”交给“删除照片”。

这样开关由 FileMann 控制，但真正的相册删除仍由持有原始 Photos 输入的快捷指令完成，避免 FileMann 根据文件名猜测照片身份。

## 签名与 Bundle ID

FileMann 固定使用独立 Bundle ID：

```
com.masakacj.filemann
```

不要再改成 `tg.unitgqq2709.tool1`，因为该 Bundle ID 已被其他 App 使用；iOS 会把相同 Bundle ID 视为同一个 App，从而发生覆盖安装。

你当前上传的 mobileprovision 是精确绑定到：

```
tg.unitgqq2709.tool1
```

因此这份描述文件不能用于安装当前这个独立 Bundle ID 的 FileMann。需要另一份匹配 `com.masakacj.filemann` 的描述文件，或者允许自定义 Bundle ID 的 wildcard profile。

IPA 不包含 Share Extension，也不依赖 App Group。

## WebDAV 本地 / 远程双地址

WebDAV 现在支持两个地址：

```
本地地址  http://192.168.x.x:5000/Share
远程地址  https://nas.example.com/Share
```

连接策略固定为：

```
先探测本地地址
→ 本地可达：使用本地
→ 本地不可达：自动使用远程
```

归档、目录浏览和 NAS 媒体浏览都使用同一套策略。

外网 WebDAV 只接受可信 HTTPS，HTTP 公网连接不会进入上传候选列表；证书错误不会被忽略。

## NAS 媒体浏览

主界面右上角的“云盘”按钮可以直接浏览当前 WebDAV 归档目录中的图片和视频。

- 目录使用 WebDAV PROPFIND 懒加载。
- 图片缩略图只在进入屏幕后按需下载，并写入本地缩略图缓存。
- 图片全屏查看支持双指放大。
- 视频使用 AVAssetResourceLoader + HTTP Range 分段读取，不会先完整下载视频再播放。
- 远程视频保留 FileMann 的手势播放器：
  - 左侧点击：上一帧
  - 右侧点击：下一帧
  - 中间点击：播放 / 暂停
  - 左侧长按：1.5× 倒退
  - 右侧长按：1.5× 快进
  - 下方区域长按并左右拖动：逐帧拖动
  - 双指：局部放大
- 视频 Range 请求会优先使用当前可用的本地地址，并保留远程地址作为备用。


## 独立 NAS Tab

主界面现在分成两个底部 Tab：

```
本地
NAS
```

“本地”负责手机媒体、快捷指令导入和归档任务；“NAS”专门负责 WebDAV 远程目录、图片和视频浏览。NAS Tab 仍然使用本地优先、远程失败回退策略。


## 缓存管理

设置页新增缓存管理：

- 显示当前缓存占用。
- 可一键“清理缓存”。
- 最大缓存支持 256 MB / 512 MB / 1 GB / 2 GB / 4 GB，默认 512 MB。
- NAS 原图、NAS 缩略图统一计入总上限，超过上限后按最久未使用顺序自动淘汰。
- 启动时会清理旧版本遗留的 URLSession 网络磁盘缓存。
- 清理缓存不会删除本地媒体库、Shortcut Inbox、归档任务或 NAS 文件。


## 存储占用

设置页会分别显示：

- FileMann 私有本地媒体（Application Support / FileMann / Media / Originals）
- Shortcut Inbox
- NAS 图片/缩略图缓存
- 元数据与临时文件
- 可管理合计

“清理 NAS 缓存”只清可重建缓存；如果 iPhone“存储空间”仍显示数 GB，通常是历史导入到 FileMann 私有媒体库的原图/视频。

可通过“删除 FileMann 本地媒体”单独清理这些文件。存在未完成归档任务时，该操作会被禁用，避免误删仍待上传的源文件。外部映射文件夹和 NAS 文件不会被删除。
